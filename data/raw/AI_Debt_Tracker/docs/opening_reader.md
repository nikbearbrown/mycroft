# The opening-ledger reader (agent start) — week 6

> Generated by `scripts/opening_eval.py score`. The reader: `src/ai_debt_tracker/graph/nodes/opening.py`. Every reading, with the rows and cells it cites: `$AI_DEBT_DATA/week6/opening/`. Intervals are 95% bootstrap over reports.

## What it does

For each dev episode the tracker needs the debt the company owed at the start: the opening ledger. Until now that was borrowed from the answer key (oracle start). The opening-ledger reader reads it from the report itself: code finds the debt tables, `qwen3:4b` points at the rows that are one instrument and at the column for the period end (a model judgment, P8), and code parses every value from the cited cell and the row's label with the answer key's own label parser. `rules` is the same reader with no model: the best table, rows naming a coupon or a year, and the period-end column found from the header's dates.

It is graded on the **94 distinct opening reports** of the 95 dev episodes — the reports B0 carries forward — against the answer key's record of each report: per bond where the report itemises its bonds (L1), per offering (L2), and total debt within 2%.

## The first pass, before P61

The first pass was scored on these same dev reports, and two code defects were found in it (P61): a rate column read as the amount when the header names one column per cell (Salesforce's 10-K and the 10-Q after it: six coupons read as amounts), and the units of a table whose caption the parser cut before "(in thousands)" (Super Micro: a total read in billions). A table of *available* borrowings now scores as off-topic. They were fixed on dev, and every report was re-read with the model's saved answer; a report whose candidate tables changed was asked again. Both passes are reported. First pass: reader L1 recall 89.4% (81.8%–94.5%), precision 96.5% (91.7%–99.4%), principal right 84.6% (72.8%–94.6%), exact 25; total debt within 2% 37 of 76. Rules only: recall 81.6% (71.1%–91.3%), precision 95.4% (90.1%–98.9%); total debt 33 of 76. First-pass readings: `$AI_DEBT_DATA/week6/opening_run1/`.

The first pass stored only 3,000 characters of each model answer, so the 9 longest answers could not be reused and were asked again. The model's answer is not the same from run to run: bonds matched, first pass → second, Broadcom 10-K 2024-10-31 (37 → 37); Broadcom 10-Q 2025-01-31 (36 → 22); Broadcom 10-Q 2025-04-30 (36 → 40); IBM 10-Q 2024-06-30 (— → —); IBM 10-Q 2024-09-30 (— → —); IBM 10-Q 2025-03-31 (— → —); Intel 10-K 2023-12-31 (— → —); Intel 10-K 2024-12-31 (31 → 31); Oracle 10-K 2024-05-31 (39 → 39). ## Who decided what

Which rows are instruments, their kinds and which column is the period end are `qwen3:4b`'s judgments (P8), flagged in every reading. Every number was parsed by code from a cited cell or label. Which report to read is B0's choice, made with the answer key's itemisation: the same document for both starts, so the comparison isolates reading; in live mode the agent would read the latest report and could not walk back by the key.
