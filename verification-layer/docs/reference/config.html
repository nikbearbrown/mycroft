    Environment variables#

    Read from the process environment; web/server.py loads a .env file first (searching upward from the working directory). .env is gitignored: never commit it, and never paste its contents anywhere. .env.example is the template.

    Generated: every os.environ / os.getenv read in runtime code (tests and archive excluded), with the default the code falls back to.

    VariableDefault in codeRead inIn .env.example

    CROSS_AGENT_MAX_CONCURRENCY'2'validation/cross_validation.pyno

    LANGCHAIN_MODEL'llama3.2'web/server.pyyes

    TAVILY_API_KEY(none)adapters/langchain_adapter.py, adapters/registry.pyyes

    A variable read with no default in code is required only on the path that uses it (for example, GEMINI_API_KEY only for a Gemini-family model).

    Runtime settings#

    The server also holds a small config in memory, shared by every request until the process restarts. It is read with GET /api/config and changed with POST /api/config (unauthenticated; see audit-criticals), or from the review app's Settings page.

    SettingDefaultMeaning
    modelLANGCHAIN_MODEL, else llama3.2the model agents run on; the family is inferred from the name
    temperature0.0sampling temperature
    seed42Ollama seed, stored with each run for replay (Gemini has none)
    agent_idexternalthe chat run's agent identity
    confidence_score0.75the chat run's starting confidence
    consistency_probefalseopt-in, but the probe runs anyway for any non-Gemini model
    providerlangchainfixed; read by the registry

    A compare request can also override the model for one agent (agent_a_model, agent_b_model), the pairing, and the contradiction rule. See HTTP API.
